# 💳 Billing Microservice (Symfony Senior Architecture)

Высоконагруженный микросервис биллинга и управления балансом пользователей. Спроектирован по канонам чистой архитектуры с акцентом на изоляцию бизнес-логики, отказоустойчивость и безопасность данных.

## 🏗️ Архитектурный стек
* **Domain-Driven Design (DDD)** и **Hexagonal Architecture (Ports and Adapters)** — полное разделение домена, сценариев и инфраструктуры. Домен не зависит от фреймворка и ORM.
* **CQRS (Command Query Responsibility Segregation)** — разделение потоков записи (`command.bus`) и чтения (`query.bus`).
* **Event-Driven & Async Oueues** — публикация доменных событий в асинхронную шину (`event.bus`) через встроенный транспорт Symfony Messenger на базе PostgreSQL.
* **Doctrine ORM Data Mapper (XML Mapping)** — конфигурация базы данных полностью изолирована от сущностей PHP.
* **Doctrine DBAL (Bypass ORM for Reads)** — оптимизированное сверхбыстрое чтение данных на чистом SQL в обход ORM ядра.

## 🚀 Быстрый старт (Локальный режим)

### 1. Требования
* PHP 8.3+ (с расширением `pdo_pgsql`)
* PostgreSQL 16+

### 2. Настройка окружения
Создайте или отредактируйте файл `.env.local` в корне проекта и укажите доступы к вашей локальной базе данных PostgreSQL:
```text
DATABASE_URL="postgresql://postgres:пароль@127.0.0.1:5432/billing_service?serverVersion=16&charset=utf8"
MESSENGER_TRANSPORT_DSN="doctrine://default?auto_setup=0"
```

### 3. Инициализация базы данных и кэша
Выполните команды в терминале для сборки карты классов, очистки кэша и развертывания структуры таблиц:
```bash
# Обновление автозагрузки Composer
composer dump-autoload -o

# Принудительное пересоздание чистой схемы в PostgreSQL
php bin/console doctrine:schema:drop --force --full-database
php bin/console doctrine:schema:create
```

## 🛠️ Основные команды

### 🧪 Запуск тестов (Unit & Integration)
Проект покрыт молниеносными доменными тестами и сквозными интеграционными тестами API (выполняются в изолированном тестовом окружении за 0.001 секунды):
```bash
# Подготовка тестовой БД (выполняется один раз)
APP_ENV=test php bin/console doctrine:schema:update --force

# Запуск тестового раннера PHPUnit
php bin/phpunit
```

### 🏃‍♂️ Запуск фонового обработчика очередей (Worker)
Поскольку доменные события обрабатываются асинхронно, для отправки уведомлений и выполнения побочных эффектов запустите воркер в отдельном окне терминала:
```bash
php bin/console messenger:consume async -vv
```

### 💻 Пополнение аккаунта (Консоль администратора)
Идемпотентная CLI-команда для управления балансом. Если указанного UUID аккаунта ещё нет в PostgreSQL, команда автоматически создаст новый профиль с нулевым балансом, после чего зачислит на него указанную сумму:
```bash
php bin/console app:billing:deposit 2c21966a-b2be-4977-bc60-d26b528a475d 15.50 USD
```

## 🔌 API Эндпоинты (REST)

* **`POST /api/v1/accounts/{id}/deposit`** — Пополнение баланса. Принимает JSON `{"amount": 500, "currency": "USD"}` (сумма передается в минимальных неделимых единицах — центах/копейках). Возвращает статус `202 Accepted`.
* **`GET /api/v1/accounts/{id}/balance`** — Сверхбыстрое чтение текущего баланса напрямую через Doctrine DBAL. Возвращает привычный формат с плавающей точкой (float).

## 🔒 Механизмы надежности и защиты данных
1. **Защита от Race Condition (Состояние гонки):** Логика изменения баланса использует пессимистические блокировки PostgreSQL на уровне СУБД (`SELECT FOR UPDATE`). Два параллельных списания никогда не уведут баланс в овердрафт.
2. **Сквозная валидация DTO:** Входящие данные автоматически валидируются на уровне промежуточного ПО (Messenger Middleware) до открытия транзакции БД.
3. **Глобальный ExceptionListener:** Все бизнес-исключения домена автоматически трансформируются в унифицированные JSON-ответы API с корректными HTTP-статусами (422 для ошибок валидации, 409 при нехватке средств). Системные ошибки (уровня 500) маскируются для безопасности данных.
