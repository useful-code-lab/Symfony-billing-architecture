# 💳 Symfony Billing Architecture — биллинг с CQRS, DDD и безопасным управлением балансом

Практический пример **бэкенд-сервиса для управления балансами и финансовыми операциями** на Symfony 7 и PHP 8.3.

Проект показывает, как построить биллинг, в котором бизнес-логика изолирована от Symfony и Doctrine, чтение и запись разделены, операции с балансом защищены от конкурентных изменений, а побочные действия могут выполняться асинхронно.

## 🎯 Что вы получите, изучив проект

Репозиторий полезен разработчикам, которые хотят увидеть **не просто набор Symfony-компонентов, а пример их совместного применения в бизнес-сценарии**.

На проекте можно изучить:

* как организовать бизнес-логику по принципам **DDD**;
* как отделить доменную модель от Symfony и Doctrine;
* как применять **Hexagonal Architecture / Ports & Adapters**;
* как разделять операции чтения и изменения данных с помощью **CQRS**;
* как организовать команды, запросы и обработчики;
* как использовать **Symfony Messenger** для асинхронной обработки событий;
* как работать с Doctrine ORM и DBAL для разных типов операций;
* как защищать изменение баланса от **Race Condition**;
* как применять транзакции и блокировки PostgreSQL;
* как валидировать входные данные до выполнения бизнес-операции;
* как превращать доменные исключения в понятные HTTP-ответы;
* как писать **unit- и integration-тесты** для бизнес-критичного кода.

Проект можно использовать как **учебный шаблон архитектуры**, основу для собственного сервиса или источник отдельных решений для существующего Symfony-приложения.

## 💡 Какую проблему решает проект

Финансовые операции требуют большей надёжности, чем обычное изменение CRUD-сущности.

Например, если несколько запросов одновременно изменяют один баланс, приложение должно гарантировать, что операции не потеряются и данные не окажутся в некорректном состоянии.

Этот проект демонстрирует подход, при котором:

```text
HTTP / CLI
    ↓
Validation
    ↓
Command / Query
    ↓
Application Layer
    ↓
Domain
    ↓
Infrastructure
    ↓
PostgreSQL
```

При этом доменная логика не привязывается непосредственно к Symfony-контроллерам или Doctrine Entity.

## 🏗️ Архитектура

### Domain-Driven Design

Домен содержит бизнес-правила работы с аккаунтами, балансами и финансовыми операциями.

Это позволяет переносить бизнес-логику между разными интерфейсами — например, REST API и CLI — без дублирования правил.

### Hexagonal Architecture

Зависимости направлены внутрь:

```text
Infrastructure
      ↓
Application
      ↓
Domain
```

Фреймворк, база данных и транспорт сообщений выступают инфраструктурными адаптерами, а не частью бизнес-ядра.

### CQRS

Запись и чтение разделены на разные сценарии.

**Command:**

```text
Deposit → изменение баланса
```

**Query:**

```text
GetBalance → получение текущего баланса
```

Это позволяет независимо оптимизировать операции записи и чтения.

## ⚡ Быстрое чтение через Doctrine DBAL

Для получения баланса необязательно загружать полноценную ORM-модель.

Чтение выполняется через Doctrine DBAL и SQL-запрос:

```text
API
 ↓
Query
 ↓
DBAL
 ↓
PostgreSQL
```

Такой подход полезен для сценариев, где требуется получать небольшие наборы данных без дополнительной работы ORM.

## 🔐 Безопасное изменение баланса

Изменение финансового состояния защищено от конкурентного доступа.

При операции изменения баланса используется блокировка строки PostgreSQL:

```sql
SELECT ...
FROM account
WHERE id = ?
FOR UPDATE;
```

Это позволяет корректно синхронизировать параллельные операции над одним аккаунтом.

Для разработчика проект представляет интерес как пример решения классической проблемы:

```text
Request A ─┐
           ├──→ один баланс → конкурентное изменение
Request B ─┘
```

вместо небезопасной схемы:

```text
прочитать → изменить → сохранить
```

без защиты от параллельных транзакций.

## 📨 Асинхронная обработка

Для событий используется **Symfony Messenger**.

После выполнения бизнес-операции связанные побочные действия могут передаваться в очередь:

```text
Business Operation
       ↓
Domain Event
       ↓
Messenger
       ↓
Queue
       ↓
Worker
       ↓
Side Effect
```

В качестве транспорта используется PostgreSQL.

Запуск обработчика:

```bash
php bin/console messenger:consume async -vv
```

## 🔌 REST API

### Пополнение баланса

```http
POST /api/v1/accounts/{id}/deposit
```

Пример запроса:

```json
{
    "amount": 500,
    "currency": "USD"
}
```

Сумма передаётся в минимальных неделимых единицах — например, центах.

Успешная операция возвращает:

```text
202 Accepted
```

### Получение баланса

```http
GET /api/v1/accounts/{id}/balance
```

Баланс читается через отдельный query-сценарий с использованием Doctrine DBAL.

## 💻 CLI для работы с балансом

Проект также содержит консольный сценарий:

```bash
php bin/console app:billing:deposit \
    2c21966a-b2be-4977-bc60-d26b528a475d \
    15.50 \
    USD
```

Если аккаунт отсутствует, он создаётся автоматически, после чего выполняется пополнение.

Это показывает, как один и тот же application/domain layer может использоваться через разные интерфейсы:

```text
              ┌── REST API
Domain ← Application ──┼── CLI
              └── Message Bus
```

## 🛡️ Обработка ошибок

Бизнес-исключения преобразуются в единый HTTP-формат.

Например:

```text
422 → ошибка входных данных
409 → недостаточно средств / конфликт бизнес-операции
500 → внутренняя системная ошибка
```

Это позволяет отделить внутренние исключения приложения от публичного API-контракта.

## 🚀 Быстрый старт

### Требования

* PHP 8.3+
* PostgreSQL 16+
* Composer
* расширение `pdo_pgsql`

### Конфигурация

Создайте `.env.local`:

```dotenv
DATABASE_URL="postgresql://postgres:пароль@127.0.0.1:5432/billing_service?serverVersion=16&charset=utf8"
MESSENGER_TRANSPORT_DSN="doctrine://default?auto_setup=0"
```

### Установка

```bash
composer install
composer dump-autoload -o
```

Создание схемы:

```bash
php bin/console doctrine:schema:drop --force --full-database
php bin/console doctrine:schema:create
```

### Запуск тестов

```bash
APP_ENV=test php bin/console doctrine:schema:update --force
php bin/phpunit
```

### Запуск worker

```bash
php bin/console messenger:consume async -vv
```
